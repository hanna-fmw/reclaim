# Disk clean-out, 2026-09-14

Disk was at 99% (2.5 GB free). Ended at 29 GB free. What it was, and what was decided.

## Where the space went

| Item | Freed |
|---|---|
| Docker: two unused local stacks removed, then unused images pruned | ~9 GB |
| A duplicate 7.6 GB screen recording on the Desktop (the original is in Drive) | 7.6 GB |
| `node_modules` in 10 projects untouched for 30+ days | 5 GB |
| Homebrew + npm caches | 1.5 GB |

Docker's disk image did give the space back to macOS, gradually, after the prune. The old
note in `TODO-expand-scope.md` claiming it never shrinks was wrong and has been corrected.

Only the local stack still in use was kept (~6 GB). The databases of the removed stacks are
untouched: their volumes stay, so starting those projects again restores their data - it
just re-downloads the images first.

## Why reclaim missed all of it

1. It only looked for projects in `~/Documents`. They live in `_work`, `_personal`,
   `_projects` and `_system` now, so it found nothing.
2. It asked Docker how big it was. Docker was wedged (a full disk does that), so the call
   never returned and the whole scan hung.

Both fixed in v1.7 and v1.8. The timeout in v1.7 did not actually work - the docker CLI is
a Go program and Go ignores SIGALRM, so `alarm` + `exec` never fires. v1.8 runs docker as a
child process and kills it on timeout instead. Verified against a fake stuck daemon: the
preview now finishes in ~20s and still reports how much disk Docker holds.

Untested: the "Start Docker" button now quits and relaunches a stuck Docker rather than
calling `open -a` (which does nothing for a hung app). Testing it would stop running
containers.

## Decided, not yet done

A 2 TB external drive (an Xbox game drive, to be wiped) becomes: half Time Machine, half a
target for screen recordings, so meeting recordings never land on the internal disk. They
are the thing that spikes it - 5-8 GB each. Erase in Disk Utility (View > Show All
Devices), APFS for Mac-only or ExFAT to share it. Point recordings at it with Cmd+Shift+5 >
Options > Save to. Worth one test recording with the drive unplugged, to see where the Mac
puts it then.

Photos and Drive were considered and dropped: Photos is tiny here, and Drive streams -
files only occupy space while cached (~0.9 GB), unless marked "Available offline".

The real constraint is a 256 GB disk doing developer work. A bigger disk on the next Mac is
the lasting fix.
